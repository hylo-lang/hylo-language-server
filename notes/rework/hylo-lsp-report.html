Context

Where this started

PR #37 combined completion with a project model, file watching, push diagnostics, a toolchain bump and about 4,000 lines of notes. It pinned hylo-new to an unmerged branch far behind main, and LanguageServerProtocol to a personal fork. Since then hylo-new #591 made static members unselectable on instances, which contradicts the PR's own ranking design. The fork's only change was merged upstream.

Following your decisions, completion was rebuilt on a clean branch and the project-model work was parked on project-model-wip. The language server now has a core with no host attached and one driver per host. Every language rule comes from hylo-new, through small queries that each sit on their own branch.

Question 1

What are the structural elements?

Five units in two repositories. Each has a single reason to change.

HyloLanguageServerCore

lsp · Sources/HyloLanguageServerCore

The language server with no host attached. Workspace is a synchronous value that holds the open documents. Each document is analysed in its own Program on top of a standard library that is type-checked once and cached. Every feature, completion included, is a plain method that returns LanguageServerProtocol types.

Its dependencies are the front end, the LSP types and swift-log. It does not use stdio, Process, JSONRPC, Bundle, Dispatch or file watching.

Native driver

lsp · Sources/hylo-language-server

The executable that editors launch. It uses ChimeHQ's LanguageServer and JSONRPC over stdio, ArgumentParser, and the standard library bundled from disk. DocumentProvider is a plain actor around the core. Release builds use cross-module optimization.

MessageDriver

lsp · Sources/MessageDriver

MessageServer (~Copyable) takes one JSON-RPC message and returns one JSON array: queued logs, then the response, then notifications. A hand-written method switch covers every request, completion included.

Malformed JSON and messages that are neither requests, notifications nor responses get proper JSON-RPC errors. It is plain Swift, tested natively with 22 tests, including a property that every method answers exactly as the core does.

Wasm driver

lsp · Sources/hylo-language-server-wasm

A reactor module for the yukibana light worker. It exports lsp_alloc, lsp_free, lsp_init, lsp_handle and lsp_output. It is built only when HYLO_LSP_WASM is set, using hylo-new's FoundationEssentials-only toolset.

It links in debug and in release with cross-module optimization. Tools/wasm-smoke-test.mjs runs it under node:wasi and checks exact hover text, symbol names, and completion labels at a member site, an unqualified site and an argument site.

Front-end queries in hylo-new

hylo-new · lsp-integration 590b5ea (the language server's pin)
  • Program.members(of:visibleFrom:) takes the qualification's type exactly as the checker assigns it and returns what a member selection would accept, with types. Static versus instance follows the checker's own rule, including #591.
  • Program.names(visibleFrom:) returns the unqualified names visible at a scope, with lookup's own shadowing rule, including Self, Void and Never.
  • Program.assignTypes(inferringTypesOfArgument:of:) returns the types an argument may have across all viable overloads. The solver collects every error-free solution, so labels, defaults, generics and the other arguments narrow the result without any copied rules.
  • Program.knownImplementation(of:in:) finds a requirement's implementation without trapping when a conformance is ill-formed.
  • FoundationEssentials-only linking, and scope assignment on the calling thread for a reactor with no executor.
Question 2

How are they related?

Dependencies point one way: host to driver to core to front end. Only the drivers know where they run.

Arrows mean "depends on". The native driver calls the core directly. The wasm driver goes through MessageDriver, which is how its behaviour is tested natively.

How completion works

  1. The lexer finds the completion site: the word touching the cursor, including keyword-shaped prefixes such as as or if, but never inside comments or string literals. The word is replaced by a sentinel name, so x., T., .m and half-typed names all parse.
  2. The edited copy is scoped. If the sentinel is an implicit member inside a call argument, the copy is typed with assignTypes(inferringTypesOfArgument:of:), which returns the argument's possible types across every viable overload. Otherwise it is typed normally. The sentinel is found again by its position, not by its name.
  3. Qualified site: members(of:) on the qualification's type as the checker assigned it. Unqualified site: names(visibleFrom:). Argument site: members(of: Metatype<T>) for each possible type T. A trait requirement and its implementation are offered once, using knownImplementation.
  4. Presentation is the only logic the language server owns:
    • call snippets, signatures in labelDetails, and overload disambiguation
    • a self. prefix for instance members (types visible lexically don't get it)
    • Point(x:y:) offered when the typed prefix is a subsequence of the type name; the list is marked incomplete whenever such items were left out

Question 3

What principles guide these answers?

Four principles decided where each line of code lives.

The type checker is the single source of truth.

The language server never decides what is static, visible, shadowed, applicable or well-typed. Listing is built on resolution without changing it, and argument types come from the solver itself.

PR #37's own copy of qualificationForSelection went out of date the moment #591 landed. Any change to resolution or typing had to clear your bar and come with evidence: hc built before and after each branch, compared over 603 inputs.

Hosts sit at the edge.

Transport, threading, file access and the standard library's location belong to the drivers. The core is synchronous and gets everything as values.

The browser has no stdio, no Process and no executor. A synchronous core can be called directly from a wasm export, and the native driver adds concurrency around it.

Pay only for what each host links.

Each driver is its own target with its own dependencies. The wasm build links FoundationEssentials, not full Foundation and ICU. External packages are patched locally and minimally, and are not forked.

Full Foundation would add about 15.5 MB gzipped. The final wasm module is 5.98 MB gzipped.

Properties pin behaviour; examples document it.

Every branch was written test-first. Where a law exists, a seeded generator checks it and shrinks failures to a small program:

  • listing agrees with what the type checker accepts
  • argument types are exactly those the checker accepts for that argument
  • offered completions resolve, and every name that would resolve is offered
  • completion answers at every position of random, even broken, programs
  • MessageServer answers exactly as the core does

Deliberately broken versions of the code were caught by these checks. That is how a property that had become trivially true was found and replaced.

Your call

Decisions before merging

Publishing: both language-server branches pin hylo-new 590b5ea, which exists only in your local clone. The hylo-new branches have to reach a remote before CI can check out the submodule. The release.yml build with cross-module optimization also has to run once on macOS, Windows and Linux arm64.
  1. Typing changes in the pin. These need your approval:
    • implicit-member-arguments: without it, the property test of argument completion fails for seeds 0, 7, 10, 12, 13 and 22, because the checker rejects every .x in an argument.
    • static-variable-selection.
    • unqualified-new: it only replaces a crash with a diagnostic.
    extension-member-introducers stays a separate proposal.
  2. Incomplete argument lists. Completing a(.| against overloads with more parameters returns nothing. Supporting it would need an open-ended matching mode used only by the argument-type query.
  3. Member semantics that completion currently mirrors from the checker:
    • a.init on an instance
    • a stored property on its type, A.x
    • an unqualified x inside a method type-checks without self.
    • struct A is P { type X = Void } is rejected
    Which of these are intended?
  4. Incomplete standard library. Code that uses a missing standard-library entity, such as an integer literal when Int is missing, still crashes the front end. Should it be typed as an error instead? That would be a type-checker change.
  5. Narrower argument completion. Should argument completion offer only members whose type matches the expected type? Today it offers every static member of each possible type.
  6. Incomplete-list rule. After a typed prefix, the list is usually marked incomplete, so clients re-ask on every keystroke. Each re-ask costs one type check.
  7. Test runtime. The property that completes at every position takes about 2 minutes with 25 seeds. Keep checking every position, or only token boundaries?
  8. Upstream patches in /home/hylo/wt/deps:
    • LanguageServerProtocol: header trimming and Snippet left out of WASI builds
    • JSONRPC: the stdio channel built only where Dispatch exists
    • BigInt: Decimal conversion without NSDecimalRound
    Upstream them?
  9. Unreported hylo-new crashes during lowering:
    • #133
    • an unbound member such as A.f
    • a static let declared in an extension
    Draft issues?
